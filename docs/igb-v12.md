# Alchemy IGB version 12 save layout

Derived 2026-10-09 from the bytes of six saves: PS4 SWAP Force slot (CUSA00024-SAVEDATA01) and
profile (SAVEDATA04), Wii U SWAP Force SWAPFORCE_1.sav and SWAPFORCE_OPTIONS.sav, Wii U
Imaginators IMAGINATORS_3.sav and IMAGINATORS_OPTIONS.sav. `igb_parse` in `pst.py` is the
executable form of this document: it refuses any file that breaks a rule marked PROVEN here, and
`pst save-convert` uses it. `check.py` round-trips `fixtures/swapforce-global-ps4.igb` (the PS4
profile save, trimmed to its data, with the owner id at 0x98 zeroed and every progress block
zero) through both byte orders.

PROVEN means the rule holds in every input file it applies to and the parser enforces it.
GUESSED means the data is consistent with it but does not force it. Where a rule rests on fewer
files than six, the scope is named.

## General rules

- Byte order: the u32 at 0x28 reads 0xFADA in the file's order. PS4 files are little-endian, Wii U
  files big-endian. PROVEN.
- Every multi-byte value is in the file's order, with one exception: the summary values at the
  start of the file are little-endian in every file, Wii U included. PROVEN (the Wii U values only
  make sense read little-endian: save_version 0x37 = 55 in both SWAP Force slots, brightness
  -1.0 and 1.0 as floats).
- Nothing in the file is aligned to the file offset. Records follow each other byte for byte
  (the PS4 slot's object buffer starts at 0x6cb5, for example). PROVEN. The only
  padding is: meta-object names rounded up to an even length, 3 bytes after every 1-byte Bool or
  Char field, and each memory block rounded up to 4 bytes. PROVEN. Padding bytes are often
  uninitialised junk on the Wii U (`01 fb 98 30` for a true Bool, `__internalObjectBase\0d`
  for a name) and must be copied, not zeroed. PROVEN.
- A "size incl." below counts its own 4 bytes. PROVEN for each section where it is used.
- The single byte at 0xf7 in the PS4 slot is string 1 of the string pool: length 1 at 0xf3, one
  NUL byte. It is not a 1-byte field. PROVEN.

## Header (0x00, 12 x u32)

| word | meaning | status |
|---|---|---|
| [0] | entry buffer size in bytes | PROVEN |
| [1] | entry count | PROVEN |
| [2] | meta-object buffer size | PROVEN |
| [3] | meta-object count | PROVEN |
| [4] | object buffer size | PROVEN |
| [5] | object count | PROVEN (equals the objects walked and [5]+[7] = index count) |
| [6] | memory buffer size | PROVEN |
| [7] | memory block count | PROVEN |
| [8] | meta-field buffer size | PROVEN |
| [9] | meta-field count | PROVEN |
| [10] | magic 0xFADA | PROVEN |
| [11] | low 16 bits version 12, high 16 bits flags | version PROVEN; flags below |

Flags seen: 0xb000 in five files, 0xb400 in IMAGINATORS_3. 0x8000 has_info (the info list index
exists), 0x2000 shared entries, 0x1000 memory pool names: these names come from the reference
reader and are GUESSED for version 12, since every input has all three. 0x0400 goes with the
hash-name table, GUESSED from one file. The parser refuses any other flag set.

The version-12 differences from the reference reader: a summary block sits at 0x30 before the
string pool, there is no alignment buffer between meta-fields and meta-objects, a memory pool id
table follows the pool names, and fields are serialized at fixed per-type sizes rather than at
the declared size. All PROVEN by the walk tiling every file.

## Summary block (0x30)

u32 buffer count, always 3 (PROVEN; the parser refuses other values). Then three buffers, each a
u32 byte count (not incl.) followed by that many bytes:

1. Descriptors, 12 bytes each: u32 value type, u32 name offset into buffer 2, u32 value offset
   into buffer 3. Value type 0 is an int, 1 a float (GUESSED from the names and values:
   percent_complete and brightness_value are type 1 and decode as floats). The value offset is
   always 4 x the descriptor number. PROVEN.
2. Names: NUL-terminated ASCII, back to back (save_version, num_skylaners, percent_complete,
   credits_watched, portal_master_display_rank in the slots). PROVEN.
3. Values: 4 bytes per descriptor, little-endian in every file. PROVEN.

## String pool

u32 size incl., u32 count, then count strings each as u32 length and that many bytes. Length
counts the terminating NUL. String 0 is always length 0 (the null string). PROVEN.

## Meta-field buffer (header [8] bytes, [9] records)

[9] static records of 12 bytes: u32 name length, u32 1, u32 0. Then the names back to back, each
exactly name length bytes, NUL-terminated, no padding. PROVEN. The 1 and 0 are presumably a major
and minor version: GUESSED. The record index is the type index every other part uses.

## Meta-object buffer (header [2] bytes, [3] records)

[3] static records of 24 bytes: u32 name length, u32 1, u32 0, u32 field count, i32 parent
meta-object index (-1 for the root), u32 slot count. Then per meta-object, in order: its name
(name length bytes, which is strlen + 1 rounded up to even, the pad byte is junk on the Wii U),
then field count records of 3 x u16: meta-field type index, slot, declared size. PROVEN.
Each meta-object lists its inherited fields too. PROVEN (igDirEntry repeats igNamedObject's String
at slot 0). The slot count is the total slot count including slots that are never serialized
(igDirEntry has 3 slots and one field): GUESSED.

The declared size is the in-memory size and differs by platform: String and ObjectRef 8 on PS4, 4
on Wii U; MemoryRef 16 vs 8; Vector 24 vs 12. It is not the serialized size. PROVEN.

## Hash-name table (IMAGINATORS_3 only, flag 0x0400)

u32 size incl., u32 table count (1), u32 n, n x u32 name hash, n NUL-terminated names. Layout
PROVEN for that one file (280 names end exactly at the size). The hashes are real u32 values: the
Handle fields resolve through them (0x4a98ee98 is gamevariables). The meaning of the 1 is
GUESSED; the parser refuses any other value.

## Memory pool names

u32 size incl., u32 count, count NUL-terminated names (MP_PERMANENT, Temporary, ...). PROVEN.

## Memory pool id table

u32 size incl., then one u32 per pool name: size = 4 + 4 x pool name count. PROVEN. That the
values are pool ids is GUESSED: every pool id in a directory entry appears in this table.

## Directory entries (header [0] bytes, [1] entries)

Each entry: u32 meta-object index, u32 entry size incl. the 8 header bytes, then the fields of
that meta-object serialized as in the field table below. PROVEN. Only two entry types occur and
the parser refuses others:

- igObjectDirEntry: String slot 0 (always 0), Int slot 4 = meta-object index of the object, Int
  slot 5 = pool id. Slot 4 equals the type word of every object it describes. PROVEN.
- igMemoryDirEntry: String slot 0, Int slot 3 = element count, Int slot 6 = meta-field index of
  the element type, Bool slot 7 (always true), Int slot 8, Int slot 9 = pool id. Count and element
  type PROVEN by the memory buffer totals. Slot 8 is GUESSED to be the in-memory element alignment:
  PS4 writes 8 for ObjectRef, String and Name blocks and 4 for UnsignedInt, the Wii U writes 4
  everywhere.

With shared entries, many index positions point at one entry. PROVEN (755 index positions, 36
entries in the PS4 slot).

## Index

u32 size incl., u32 count, count x u16 entry numbers, no padding even for an odd count. Count =
header [5] + [7]. PROVEN. Index position i is "object or block i": everything that refers to an
object or a memory block uses its index position.

## Info list index

One u32: the index position of the igInfoList object. PROVEN in all six.

## Object buffer (header [4] bytes, [5] objects)

For each index position whose entry is an igObjectDirEntry, in index order: u32 meta-object
index, u32 object size incl. the 8 header bytes, then the meta-object's fields in list order.
PROVEN.

## Memory buffer (header [6] bytes, [7] blocks)

For each index position whose entry is an igMemoryDirEntry, in index order: element count x
element size bytes, then 0 to 3 padding bytes to a multiple of 4. PROVEN: the totals match header
[6] exactly in all six files, and only padding makes IMAGINATORS_OPTIONS add up (83 Char blocks of
185 bytes and one Bool block of 9 bytes, 252 bytes of padding).

## Tail

SWAP Force files: zero bytes to the end of the 0x19000-byte file. PROVEN. Imaginators files: zero
bytes, then a non-zero u32 in the last 4 bytes of the 0xa0000-byte file (bc05d502 in
IMAGINATORS_3, 8f92887a in IMAGINATORS_OPTIONS). Its meaning is unknown. It is not CRC-32,
inverted CRC-32, Adler-32 or a 32-bit byte sum, read in either byte order, over any of: the
structured data, the file without its last 4 bytes, the file with them zeroed, or the file from
offset 4 or 0x30. The converter refuses such a file.

## Field serialization (objects and entries)

| meta-field type | bytes | swapped as | status |
|---|---|---|---|
| igObjectRefMetaField | 4 | u32 | PROVEN; -1 or the index position of an object |
| igMemoryRefMetaField | 4 | u32 | PROVEN; the index position of a block, or -1, -2, -3 for empty lists |
| igStringMetaField | 4 | u32 | PROVEN; a string pool index |
| igIntMetaField, igUnsignedIntMetaField, igEnumMetaField | 4 | u32 | PROVEN |
| igFloatMetaField, igTimeMetaField | 4 | u32 | PROVEN size; a float swaps as its 4 bytes |
| igBoolMetaField, igCharMetaField | 4 | value byte first, 3 junk bytes, none swapped | PROVEN (Wii U `01 fb 98 30`, `1e 0c ef d0`) |
| igVectorMetaField | 8 | 2 x u32 | PROVEN (`fe ff ff ff 00 00 00 00` on PS4, `ff ff ff fe 00 00 00 00` on Wii U) |
| igHandleMetaField | 8 | 2 x u32: name hash, namespace hash | PROVEN in IMAGINATORS_3 only |
| igBitFieldMetaField | 0 | stored inside the preceding UnsignedInt | PROVEN by the object sizes in Imaginators |
| igVec3fMetaField | 12 | not decided | size PROVEN, every sample is zero, the converter refuses |
| igUnsignedLongMetaField | 8 | not decided | size PROVEN, see the open question below |

Any other type in an object or entry makes the parser refuse.

## Memory element sizes

| element type | bytes | swapped as | status |
|---|---|---|---|
| ObjectRef, Int, UnsignedInt, String, Float | 4 | u32 | PROVEN |
| igNameMetaField | 8 | 2 x u32: string pool index, name hash | PROVEN cross-platform: CGameSaveData0 hashes to 0x219b2d77 in both slots |
| igHandleMetaField | 8 | 2 x u32 | size PROVEN (IMAGINATORS_OPTIONS totals), layout as for the field |
| igCharMetaField, igBoolMetaField | 1 | not swapped | PROVEN by the padding totals |

## What a byte-order conversion leaves different from a native PS4 file

The converter changes byte order only. These Wii U values stay as they are, and whether the PS4
game accepts them is not known from these files:

- Meta-object declared sizes stay 32-bit (String 4, ObjectRef 4, MemoryRef 8, Vector 12).
- Memory entry slot 8 stays 4 where the PS4 writes 8.
- The Wii U meta-field list has 336 types, lacking MountedSaveDataMetaField and
  MountedSaveDataArrayMetaField, so type indices from 26 on are 2 lower (igNameMetaField 26 vs 28,
  igTimeMetaField 36 vs 38). The file is consistent with its own list.
- The Wii U lists 76 memory pools, the PS4 78.
- Junk padding bytes stay junk.

## Open questions, with the bytes

- igUnsignedLongMetaField (IMAGINATORS_OPTIONS only): 8 bytes, declared size 8 on the Wii U. At
  0xab72 the bytes are `80 eb 50 01 b5 30 cc 7f`. Either one u64 (little-endian output
  `7f cc 30 b5 01 50 eb 80`) or two u32 in this order (`01 50 eb 80 7f cc 30 b5`). Only
  big-endian samples exist, so the bytes cannot decide it. The converter refuses.
- igVec3fMetaField (IMAGINATORS_3): presumably 3 floats, but every sample is zero.
- The Imaginators 4-byte trailer, above.
- The hash-name table count word (1) and its link to flag 0x0400 rest on one file.
